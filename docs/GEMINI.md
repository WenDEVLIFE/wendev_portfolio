# Gemini Coding Agent Guidelines & Rules

This document defines the system instructions, design standards, and coding rules for **Google Gemini** models (such as Gemini 2.5 Pro / Flash) when acting as an agent or pair programmer on this repository.

---

## 🤖 Model Optimization Profile
Gemini excels in **large context reasoning**, **structured JSON generation**, **type-safety checks**, and **logical code synthesis**. Use these guidelines to leverage these strengths:
* **Strict Type Safety**: Write comprehensive TypeScript types and interfaces. Do not use `any`.
* **Structured Output**: When generating file maps or configurations, output clean, structured schemas.
* **Component Completeness**: Do not use placeholders or lazy comments like `// ... rest of code`. Generate complete, copy-pasteable files.

---

## 💻 Tech Stack & Architecture Rules

All code generated by Gemini must adhere to the following setup:

### 1. Next.js (App Router) & React 19
* **Routing**: Follow the App Router structure (`app/page.tsx`, `app/api/.../route.ts`).
* **Client vs. Server Components**: 
  * Use `"use client"` *only* when the component uses React hooks (`useState`, `useEffect`, `useRef`, etc.) or browser APIs.
  * Keep layouts and high-level page shells as Server Components for fast initial loads and SEO efficiency.
* **Imports**: Use the `@/` path alias for absolute imports from the project root (e.g., `@/components/ui/ChatBot`).

### 2. Styling (Tailwind CSS v4)
* **Tailwind v4 Integration**: Avoid legacy v3 config methods. Write utility classes inline.
* **Theme & Aesthetics**: Maintain the **premium, dark-mode glassmorphic aesthetic**:
  * Backdrops: Use transparent white overlays (`bg-white/5` or `bg-white/[0.02]`) with background blurs (`backdrop-blur-2xl` or `backdrop-blur-[24px]`).
  * Borders: Subtle, semi-transparent borders (`border-white/10` or `border-white/[0.06]`).
  * Text colors: Use curated text scales (`text-white`, `text-neutral-300`, `text-neutral-400`, `text-neutral-500`). Avoid generic vibrant primary colors unless styling active states.

### 3. Database & Auth (Firebase)
* **Client SDK**: Use client-side Firebase for user interactions.
* **Server SDK (`firebase-admin`)**: Use the Firebase Admin SDK inside serverless API routes (`app/api/...`) for secure database and auth checks. Do not expose administrative service credentials on client components.

## 🛠️ Coding Guidelines & Quality Controls

### 1. Code Preservation & Comment Integrity
* **Do not remove comments**: Retain existing docstrings, explanation blocks, or warning comments unless they are directly contradicted by the new requirements.
* **Inline comments**: Write clear, descriptive comments for complex conditional logic or math equations (e.g., in Framer Motion transition curves).

### 2. Error Handling & Validation
* **API Handlers**: Always wrap API operations inside `try-catch` structures. Return informative, typed JSON responses:
  ```typescript
  return NextResponse.json({ error: "Descriptive error message" }, { status: 400 });
  ```
* **Form Inputs**: Sanitize inputs and enforce validation rules before dispatching database transactions.
